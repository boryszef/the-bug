# Feature: Internationalisation (i18n) — English + Polish

## Why

All player-facing text was hard-coded English: `format!`-composed sentences
in `Game`, hard-coded panel titles/hints in `src/ui/*.rs`, and quest
name/description text baked into `src/game/quest.rs`'s `QUESTS` table. Polish
needs grammatical case (genitive, locative), different prepositions, and
CLDR-style plural categories — not achievable by swapping words into an
English template. See `docs/i18n-plan.md`'s git history for the original
design discussion; this doc records the shape that shipped.

## Outcome

Language is detected **once at startup** — `--lang xx` wins, then
`$LC_ALL`/`$LC_MESSAGES`/`$LANG` (skipping unset, empty, `C`, or `POSIX`),
else English (`i18n::detect`, `src/i18n/mod.rs`) — but can also be changed
in-game via the `⚙` cog dropdown (`Language::ALL`/`display_name`,
`src/i18n/mod.rs`; the switch itself lives in `src/gui/mod.rs`, alongside
the theme/font-size controls — see `docs/accessibility.md`). The choice
isn't persisted: it resets to the detected/`--lang` value on the next
launch, same as theme and font size.

Localisation runs on **Project Fluent**, via `i18n-embed` + `i18n-embed-fl`:
- `.ftl` resources live in `src/i18n/locales/{en,pl}/main.ftl`, embedded at
  compile time via `rust-embed` (`Localizations`).
- Each `Language` gets its own `FluentLanguageLoader`, built once
  (`OnceLock`) with its own bundle plus the English fallback bundle behind
  it.
- The `fl!()` macro checks every literal message id against the English
  (fallback) `.ftl` at *compile* time — this is what stands in for the
  `match`-exhaustiveness a hand-written translation `enum` would otherwise
  give the compiler for free. A runtime table test
  (`i18n::tests::every_event_kind_renders_in_every_language`) covers the
  rest: every `EventKind` variant, in every `Language`, must resolve to a
  non-empty message.
- Grammatical case is resolved where it's actually needed, via Fluent
  message **attributes**: terrain names carry a `.locative` attribute (used
  by `event-found`, e.g. `"w lesie"` instead of a bolted-on "in the"), and
  item names carry a `.genitive` attribute (used by the "not enough X"
  events). Everywhere else, nouns render in the nominative — see *Out of
  scope*.
- Fluent **select expressions** drive the `Experimented` event's "(new
  recipe!)" suffix (a `$newly_learned` arg selecting `[yes]`/`*[no]`)
  instead of a Rust-side string suffix.

`Game` no longer composes text. `src/game/event.rs`'s `EventKind` enum has
one variant per `Game::log(...)` call site (`Awoke`, `Found`,
`QuestAccepted`, `QuestCompleted`, `Crafted`, `ExperimentFailed`,
`Experimented`, `Disassembled`, and others); `Event` is `{ kind: EventKind,
elapsed: Duration }`, and `EventCategory` (used for log colouring) is
derived from `kind.category()` rather than stored. `Disassembled` stores
only the `item` taken apart — the recovered consumables are re-derived via
`disassembly_for` at render time, not duplicated in the enum. `EventKind`
derives `Clone` rather than `Copy`, since `ExperimentFailed`/`Experimented`
carry a runtime `Vec<(Item, u32)>` (the player's chosen combination —
`ItemSelection` is unbounded, so this can't be a fixed-size `Copy` type).
(A handful of pure-refusal variants — a craft/experiment/hunt attempt
checked and refused before anything was spent — existed briefly and were
removed; see `docs/event-worthiness.md`.)

`i18n::event(kind, lang)` renders one log line; `i18n::item`/`quest_name`/
`quest_description` render names; `i18n::ui`/`ui_args` cover one-off panel
titles, hints, and labels. Every `src/ui/*.rs` panel takes a `Language` and
renders through these instead of holding its own strings.

## Scope

- `src/i18n/mod.rs` — `Language`, `detect`, the per-language loaders, and
  the wrapper functions above.
- `src/i18n/locales/{en,pl}/main.ftl` — the message/term/attribute
  definitions. `i18n.toml` (crate root) configures the `fallback_language`
  and `.ftl` location for the `fluent_language_loader!`/`fl!` macros.
- `src/game/event.rs` — `EventKind`, `EventCategory::category()`
  delegation, `Event`'s new shape.
- `src/game/mod.rs` — `Game::log` takes an `EventKind`; all ten call sites
  updated.
- `src/game/item.rs`/`map.rs` — `impl Display for Item`/`TerrainType`
  removed (naming is entirely `i18n`'s job now); `Direction`/`TerrainType`
  gained `Serialize`/`Deserialize` (needed for `EventKind` persistence).
- `src/save.rs` — `EventState` serializes `EventKind` directly instead of
  `{ category, text }`.
- `src/viewmodel/events.rs` — `RecentEvent` carries `&EventKind`, not
  `{ category, text }`.
- `src/viewmodel/crafting.rs` — `CraftOption` carries `id: &'static str`
  (the `Game::craft` lookup key) and `output: Item` (for display), not
  `name`.
- `src/ui/*.rs` — every panel (`app`, `craft`, `experiment`, `disassemble`,
  `quests`) takes a `Language` and renders through `i18n`.
- `src/main.rs` — `--lang <LANG>` alongside the existing `--load <FILE>`.
- **In-game switching** (later addition): `src/i18n/mod.rs` —
  `Language::ALL`, `Language::display_name` (each language's own endonym,
  not translated). `src/gui/mod.rs` — a language section in the `⚙`
  dropdown, alongside theme/font-size (`docs/accessibility.md`). The
  `language-label` `.ftl` key.

## Out of scope

- An on-screen language indicator outside the `⚙` dropdown itself, or
  persisting the chosen language across launches (matches theme/font-size,
  `docs/accessibility.md`).
- **Old save files.** Save files written before this change store
  pre-rendered `{ category, text }` events; that shape doesn't deserialize
  against the new `EventKind`-based `EventState`, on purpose. `load()`
  surfaces this as `io::ErrorKind::InvalidData`, same as any other malformed
  save — there is no migration path.
- Full CLDR plural-category handling for quantities. `item_with_quantity`
  (inventory/selection lists, the `describe_items` join used inside
  `Experiment*`/`Disassembled` event messages) is a plain `"<count> <name>"`
  concatenation in both languages — a faithful port of the original
  English-only behaviour, not yet driving Polish's `one`/`few`/`many`/`other`
  plural categories. A real follow-up, not required for correctness today.
- Complete Polish grammatical correctness for every interpolated noun.
  Case is resolved only where `i18n::event` explicitly asks for it (terrain
  locative in `Found`, item genitive in the two "not enough X" events);
  everything else — including the direct object in `event-found` itself —
  renders in the nominative. The Polish `.ftl` is a first draft for a native
  speaker to review and correct.
- Translating `docs/`, `README.md`, `STORY.md`, or commit messages.
- Localised inventory sort order (stays `Item` enum order).
- Footstep/walk logging. `walk()` still logs nothing — adding an
  `EventKind::Walked` would be a behaviour change, not a refactor, and was
  explicitly kept out of scope.
